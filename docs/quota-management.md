# 号池配额与自动恢复

概览的配额汇总仅包含已启用、同步状态 ready、有可用 API Key、且最近快照未显示额度耗尽的账号。5h、周、月分别汇总已用、总额与剩余额度；每类独立报告已提供和未提供数据的账号数量。汇总读取本地保存的快照，不为每次页面请求重新查询上游。

账号列表和详情统一显示 5h、周、月配额。优先使用上游 windowLimits 的对应窗口；月窗口未直接返回时，使用真实 monthlyCreditsGranted（发放总额）和 monthlyCredits（剩余额度）计算月已用量，使用订阅 currentPeriodEnd 作为月度复查时间。不按套餐名称硬编码额度，不混用不同时间获取的用量汇总。缺失总额时仍保留真实月余额，但总额保持未知。

## 自动暂停与恢复

- 任一窗口明确 exceeded，或已用量达到总额时，账号自动暂停转发，不删除账号。存在月订阅额度但月余额已耗尽时，即使月总额未提供也会暂停。
- enabled=false、quota_paused=true 标识系统暂停；quota_resume_at 和 quota_pause_reasons 保存在 PostgreSQL 中。普通手动停用不会设置自动恢复状态。
- 多个窗口同时耗尽，已知恢复时间取最晚一项。缺少完整恢复时间，或新快照仍耗尽但重置时间已过，则按现有刷新间隔定期复查。
- Worker 每 10 秒调度一次，在恢复时间到达后优先安排额度刷新。只有取得健康快照、原暂停窗口均已确认恢复、专用 Key 可用时才重新启用。刷新失败仍保留暂停，并遵守现有重试退避。
- 新快照缺少原暂停窗口，不把缺失视为恢复；重叠同步的旧结果不能覆盖新快照。服务重启后继续按数据库状态调度。
- 手动停用或详情中的“取消自动恢复”会取消自动恢复。手动启用已自动暂停的账号会立即请求复查，确认可用后恢复。
- 修改名称、分组、备注或并发不改变自动暂停归属。过期凭证需要处理凭证后再恢复同步。
