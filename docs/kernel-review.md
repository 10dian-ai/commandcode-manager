## 和本项目需求的差距

### 账号池、亲和与持久化

原实现是请求携带账号凭证的转换服务，并没有批量 Cookie 导入、凭证管理、配额同步、PostgreSQL 或 Redis 账号池。

sessionStore 与 inflightCount 位于单进程内存（proxy.mjs:189、215）。它们不能承担多个实例之间的账号调度或每账号并发限制。管理层应独立持有会话到账号的映射、并发租约和账号状态。

### Responses 的具体兼容缺口

1. convertResponsesToChat 构造结果时未保留 prompt_cache_key，handleResponses 又从这个结果读取该字段（proxy.mjs:2272、2597）。当前路径会丢失缓存键；账号亲和应在转换前由管理层独立提取。
2. previous_response_id 被明确拒绝（proxy.mjs:2564），要求客户端每轮传完整上下文。不能将这一实现视作支持全部 Responses 会话存储语义。
3. 输入主要处理具备 type 的消息项和文本，图片、文件及其他工具类型不能按已支持处理；reasoning 的加密状态也未实现（proxy.mjs:2168、2174、2212、2254）。
4. 上游 EOF 后若已有部分内容但未出现明确结束事件，代码仍可能输出 completed（proxy.mjs:2650、2678、2526）；需验证异常流不会被记录为完整成功。

### 模型和日志

- dynamicModels 是所有请求共用的全局缓存（proxy.mjs:2120），失败时返回硬编码模型表（2153-2159）。它只能作为目录参考，不能作为每个账号实际模型权限的证据。
- 原有日志侧重运行状态，完整业务请求及回复的保存、搜索、期限清理应由我们的管理层实现。
- 某些超时被转换成 429，不能在账号调度层把所有 429 都判定为额度耗尽。

### Go 账号适用性

源码包含模拟官方客户端、设备指纹伪装和反检测逻辑。存在这些代码，不能证明 Go 已获得官方 Provider API 权限，也不能保证私有通道长期可用。

可复用的通用协议转换与正常认证功能，应与这类行为分别评估；不把规避套餐或风控检查作为已验证的实现前提。当前几百个 Go 账号的实际可用接入方式仍待确认。

## 建议组件边界

在具备相应上游接入权限的前提下：

客户端 → 管理网关 → 协议适配组件 → 上游模型服务

- 管理网关：自己的访问 Key、账号选择、每账号与全局并发、亲和映射、完整业务日志。
- 后台 Worker：Cookie/凭证管理、额度同步、周期任务与上游版本检查。
- PostgreSQL：账号、配置、原始额度数据、日志与版本记录。
- Redis：同步队列、会话映射、并发租约与缓存。
- 协议适配组件：消息和流式事件转换，保持较小接口，避免和管理后台代码深度耦合。
- 若采用独立服务，它只在内部容器网络暴露，外部客户端统一访问管理网关。
- 保留未经修改的上游快照，必要兼容改动作为独立补丁记录，避免将整套后台直接写入上游单文件。

## 内核更新建议

“定期检查更新”可以实现；“定期更新保证适配”无法保证。

1. 周期检查上游提交，后台展示当前版本、候选版本、变更摘要及验证状态。
2. 下载固定提交到候选目录，保留当前运行版本，构建产物固定摘要。
3. 检查许可证和依赖变化，运行语法与接口回归。
4. 回归覆盖文本、标准工具回合、流式结束及异常、取消、缓存键保留、真实用量字段和三个目标客户端。
5. 通过后切换新请求到候选版本，旧版本完成在途请求后退出。
6. 验证失败保持当前版本；出现回归时可切回上一版本。数据库变更单独管理兼容性与回退策略。

目前公开仓库工作流只有镜像构建发布，未见自动协议测试；package.json 没有 test 或 lint 脚本。已实时核对仅有 v1.0.0 标签（0e761824c10020a4192afb249c0995bef5cd4195），没有 GitHub Release 记录，master 已包含之后的修改。因此不应把 latest 标签或构建成功等同于兼容性验证。

源码还会定期刷新官方 CLI 的版本字符串（proxy.mjs:125-145）；这不是内核代码更新，也不能代替协议变更适配。即便固定内核源码，评估运行稳定性时也需记录这类动态依赖。
